# scope-control Skill

## When it applies
This skill applies to all planning and implementation tasks where managing scope, boundaries, and preventing scope creep is important including:
- Creating implementation plans or estimating work
- Starting new features, components, or functionality
- Making changes to existing code or designs
- Breaking down larger tasks into manageable pieces
- Deciding what to include in a specific iteration or sprint
- Managing dependencies between different parts of the system
- Determining the minimum viable implementation for feedback
- Planning technical spikes or research tasks
- Setting boundaries for what is "in scope" vs "out of scope"
- Managing stakeholder expectations about what will be delivered
- Deciding when to defer functionality to future iterations

## Mandatory rules
1. Always start with a clear, specific goal or objective for the work
2. Define explicit boundaries for what is included in the current scope
3. Identify and document what is explicitly out of scope for this task
4. Break work into the smallest meaningful increments that deliver value
5. Focus on the minimum viable implementation that tests core assumptions
6. Clearly distinguish between essential features and nice-to-have enhancements
7. Respect timeboxing and iteration boundaries - don't let work expand indefinitely
8. Document assumptions and dependencies that affect scope decisions
9. Regularly check if current work still aligns with the original goal
10. Be willing to say "no" or "not now" to additional feature requests
11. Prioritize ruthlessly based on value, risk, and dependencies
12. Clearly communicate scope decisions to stakeholders and team members
13. Use version control and branching strategies to isolate experimental work
14. Define clear completion criteria and "done" definitions for tasks
15. Review and adjust scope based on feedback and learning during implementation

## Prohibited actions
1. Do NOT start work without a clear, specific goal or objective
2. Do NOT fail to define what is explicitly out of scope for the current task
3. Do NOT allow scope to expand gradually without conscious decision-making
4. Do NOT work on low-value enhancements when high-value essentials remain
5. Do NOT ignore timeboxing and let work expand to fill available time
6. Do NOT fail to document assumptions and dependencies that affect scope
7. Do NOT lose sight of the original goal while implementing details
8. Do NOT hesitate to defer or reject additional feature requests when needed
9. Do NOT fail to prioritize based on value, risk, and dependencies
10. Do NOT keep scope decisions ambiguous or undocumented
11. Do NOT work on experimental features without proper isolation strategies
12. Do NOT lack clear completion criteria or definition of "done"
13. Do NOT fail to review and adjust scope based on implementation feedback
14. Do NOT confuse activity with progress - focus on outcomes, not just effort
15. Do NOT treat scope as fixed and unchanging - it should evolve with learning
