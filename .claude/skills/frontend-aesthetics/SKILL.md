# frontend-aesthetics Skill

## When it applies
This skill applies to all frontend/UI implementation tasks including:
- Creating or modifying React components
- Styling with CSS/Tailwind
- Implementing layouts, typography, color schemes
- Adding animations, transitions, or micro-interactions
- Designing UI elements (buttons, forms, cards, etc.)
- Implementing light/dark themes
- Any visual design or styling work

## Mandatory rules
1. Always apply the DISTILLED_AESTHETICS_PROMPT guidelines for creative, distinctive designs
2. Choose beautiful, unique, and interesting fonts (avoid generic fonts like Arial, Inter, system fonts)
3. Commit to a cohesive aesthetic using CSS variables for color consistency
4. Use dominant colors with sharp accents rather than timid, evenly-distributed palettes
5. Prioritize CSS-only solutions for HTML animations and micro-interactions
6. Focus on high-impact moments (e.g., staggered page load reveals) over scattered micro-interactions
7. Create atmosphere and depth with layered CSS gradients, geometric patterns, or contextual backgrounds
8. Interpret creatively and make unexpected choices that feel genuinely designed for the context
9. Vary between light/dark themes, different fonts, and different aesthetics to avoid convergence
10. For Siva's portfolio, use a mature technical/editorial direction (not generic SaaS/dashboard)

## Prohibited actions
1. Do NOT use generic font families (Inter, Roboto, Arial, system fonts) as primary choices
2. Do NOT use clichéd color schemes (particularly purple gradients on white backgrounds)
3. Do NOT create predictable layouts or component patterns without context-specific justification
4. Do NOT implement cookie-cutter design that lacks context-specific character
5. Do NOT add decorative visuals, animation, or dependencies unless they support the page's purpose
6. Do NOT trade usability for novelty - accessibility and readability come first
7. Do NOT create designs that look like generic "AI slop" aesthetic
8. Do NOT ignore the approved implementation plan's scope or requirements
9. Do NOT apply these rules to non-frontend tasks (backend, DevOps, etc.)
10. Do NOT violate accessibility standards in pursuit of aesthetics

## Completion checks
- [ ] Uses distinctive, non-generic font choices that elevate the design
- [ ] Implements a cohesive aesthetic with CSS variables and dominant colors/sharp accents
- [ ] Includes thoughtful animations/micro-interactions that serve a purpose
- [ ] Creates atmosphere/depth through gradients, patterns, or contextual effects
- [ ] Avoids all prohibited generic AI-generated aesthetics
- [ ] Shows creative interpretation and unexpected yet appropriate design choices
- [ ] Maintains accessibility (WCAG 2.1 AA), readable contrast, responsive behavior
- [ ] Uses semantic HTML and proper keyboard navigation
- [ ] Respects `prefers-reduced-motion` settings
- [ ] Aligns with Siva's portfolio's mature technical/editorial direction
- [ ] Stays within the approved implementation plan's scope
- [ ] Never sacrifices usability for novelty
