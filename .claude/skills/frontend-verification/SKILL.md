# frontend-verification Skill

## When it applies
This skill applies to all frontend implementation tasks where verification of correctness, quality, and adherence to requirements is needed including:
- After implementing new UI components or features
- When making changes to existing frontend code
- Before considering a task complete for handoff or approval
- When implementing based on design specifications or mockups
- After fixing bugs or addressing issues in the frontend
- When implementing accessibility or responsive behavior
- Before and after refactoring frontend code
- When integrating frontend with backend APIs or services
- After implementing animations, transitions, or interactive elements
- When verifying that implementation matches approved plans

## Mandatory rules
1. Always verify that the implementation matches the approved plan specifications
2. Test functionality across multiple browsers (Chrome, Firefox, Safari, Edge)
3. Check responsive behavior at common breakpoints (mobile, tablet, desktop)
4. Verify accessibility compliance using automated and manual testing
5. Ensure all interactive elements work as expected (clicks, hovers, focus, etc.)
6. Validate that data flows correctly and UI updates appropriately
7. Check for console errors, warnings, or problematic network requests
8. Verify performance isn't significantly degraded by the implementation
9. Ensure the implementation follows established code patterns and conventions
10. Test edge cases, empty states, error states, and loading states
11. Verify that text content is properly displayed and not truncated
12. Check that images, icons, and media load correctly and have fallbacks
13. Ensure that the implementation doesn't break existing functionality
14. Verify spelling, grammar, and proper formatting of all displayed text
15. Check that the implementation works with both light and dark themes if applicable

## Prohibited actions
1. Do NOT consider a task complete without performing verification checks
2. Do NOT rely solely on visual inspection without functional testing
3. Do NOT skip browser compatibility testing assuming "it works in my browser"
4. Do NOT ignore accessibility verification because "it looks fine visually"
5. Do NOT skip responsive testing assuming the layout will adapt correctly
6. Do NOT overlook console errors, warnings, or failed network requests
7. Do NOT assume data flow is correct without verifying UI updates and state
8. Do NOT ignore performance impacts of the implementation
9. Do NOT deviate from established code patterns without justification
10. Do NOT forget to test edge cases, empty states, and error conditions
11. Do NOT assume text display is correct without checking for truncation/overflow
12. Do NOT neglect to verify media assets load correctly with proper fallbacks
13. Do NOT implement changes that break or degrade existing functionality
14. Do NOT overlook spelling, grammar, or formatting errors in displayed text
15. Do NOT forget to verify theme compatibility if the site supports multiple themes

## Completion checks
- [ ] Implementation matches all specifications in the approved plan
- [ ] Functions correctly across Chrome, Firefox, Safari, and Edge browsers
- [ ] Responsive behavior verified at mobile, tablet, and desktop breakpoints
- [ ] Accessibility compliance verified (WCAG 2.1 AA) using appropriate tools
- [ ] All interactive elements work as expected (click, hover, focus, etc.)
- [ ] Data flows correctly and UI updates appropriately based on state
- [ ] No console errors, warnings, or problematic network requests present
- [ ] Performance impact is acceptable and not significantly degraded
- [ ] Implementation follows established code patterns and conventions
- [ ] Edge cases, empty states, error states, and loading states tested
- [ ] All text content is properly displayed without truncation or overflow
- [ ] Images, icons, and media load correctly with appropriate fallbacks
- [ ] Existing functionality remains intact and unaffected by changes
- [ ] Spelling, grammar, and formatting of all displayed text verified
- [ ] Implementation works correctly with both light and dark themes (if applicable)
- [ ] Verified against any specific design mockups or specifications provided
- [ ] All verification checks documented and issues resolved before completion
